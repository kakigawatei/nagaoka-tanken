# データ収集の機会リスト（審査・コンプラを厳しくしない範囲で）

2026-07-24 masaさんの依頼「データ収集で色々できそう」を受けた棚卸し。**まだ何も実装していない設計メモ**。意思決定用。

## 0. まず前提として押さえておくべき事実

**現状、サーバー側にはプレイヤーの行動データがほとんど何も送られていない。**

- `found[]`（発見スポット）、`visits{}`（訪問回数）、`coins`/`xp`/`level`、`gacha`、`omiyage`、`makino`（牧野家育成）は**すべて端末内 localStorage だけ**。masaさんも運営として見る手段が今は無い。
- Firestore に実在するのは4種類だけ：
  - `crowd/{shopId}` … 混雑ランプの**現在値のみ**（履歴なし、上書き）
  - `cards/{cardId}` … カードのシリアル採番（発行タイムスタンプは残る）
  - `referrals` / `refcodes` … 紹介コードの集計
  - `shopOwners/{uid}` … 加盟店ログインの紐付け
- つまり「集める」と言った瞬間、ほぼ全項目が**新規実装**になる。裏を返せば、**何を送るかを一から設計できる＝最初から匿名集計だけに絞り込める**、ということでもある。これは強み。

**リスク評価の原則**：個人を識別しうる情報（氏名・連絡先・顔写真・自由記述文章・広告ID等）を一切含まない「匿名の集計カウンタ（いつ・どこで・何件）」に留める限り、個人情報保護法上の「個人情報」に該当せず、同意取得の法的義務も生じにくい。App Store審査で問題になる ATT（追跡透明性）の同意ダイアログも、**他社サービスを横断した追跡をしない限り不要**（今回の提案は全部自社アプリ内の集計のため対象外）。この原則から外れる項目（顔写真・自由記述・個人単位の行動シーケンス）だけがリスクを上げる。

## まずやるならこれ（低リスク×高価値×軽実装）Top5

1. **お店の来店匿名カウンタ**（②）— お店ピン到達／ページ閲覧の日次カウント。プレミアムプランの「実績レポート」機能に直結し、営業トークとしても即使える。
2. **混雑ランプの履歴化**（②）— 既存の `crowd/{shopId}` 書き込みにサブコレクションを足すだけ。「何曜日の何時が混むか」をお店に還元できる、実装コストが一番軽い。
3. **スポット別・時間帯別の匿名来訪カウンタ**（①）— 人気スポット把握＋自治体提供データの土台。他の項目（③のイベント効果測定）がこれに無料で相乗りできる。
4. **限定イベントスポットの発見数トラッキング**（③）— 3の仕組みに乗るだけでほぼ追加コストゼロ。花火・灯籠流しの効果測定にすぐ使える。
5. **アプリ内ミニアンケート（選択式限定）**（⑤）— 実装が軽く、プロダクト改善の声を直接拾える唯一の「能動収集」項目。

いずれも**個人非紐付けの集計カウンタ**に統一すれば、同意画面もプライバシーポリシー改訂も基本的に不要なレベルに収まる（数値の意味自体は変わるので規約に一文追記する程度は推奨）。

## 魅力的だが要注意（同意・匿名化の設計が必要）

- **周遊経路（順序＋時刻）データ**：組み合わせて見ると個人の行動パターンに近づく。k-匿名性（少人数の時間帯は表示を丸める）を設計に組み込むこと。
- **クーポン利用のお店別時系列公開**：常連客の行動が店側に推測されないよう、必ず日次集計に丸めて渡す。個々の利用者の動きを店舗管理画面にそのまま見せない。
- **★評価・口コミ**：低評価一件が炎上・お店とのトラブルの火種になりうる。最低件数未満は非表示、自由記述コメントは原則付けない（付けるなら強いモデレーション体制が前提）。
- **写真投稿（UGC画像）**：顔が映るリスクが高く「映像・生体情報を一切扱わない」という現ブランドの核と矛盾する。App Store審査でもコンテンツモデレーション体制の明示が必須になり最もハードルが高い。**今回は見送り推奨**、将来やるなら別ブランド方針として仕切り直しが必要。
- **DAU/継続率などの行動ログ全般**：匿名イベント基盤を新規に作る必要があり、「今まで何も送っていない」というシンプルさを崩す設計判断になる。まずは①②③のような「集計カウンタ」だけに留め、個々のプレイヤーの行動シーケンスをサーバーに残す設計（＝実質的な個人トラッキング）は避けること。

## 原則（このアプリのブランドを壊さないために）

- 新規に集めるデータは**個人非紐付けの集計値**に限定する（「誰が」ではなく「いつ・どこで・何件」だけを送る）。
- 位置情報は現状通り「スポット到達イベント」の点情報のみを扱い、常時トラッキングはしない。
- 氏名・連絡先・顔写真・自由記述文章・アカウント連携など個人を識別しうる情報を扱う場合のみ、利用規約／プライバシーポリシーの明記と任意参加の同意画面が必須になる。**Top5はこのラインの手前に意図的に収めてある。**
